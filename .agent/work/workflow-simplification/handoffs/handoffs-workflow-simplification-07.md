# Ticket 07 handoff

## 实现

`topic test` 运行全部无星号命令，以当前完整批次绑定结果。`branch_review` 为多票 standard 创建独立对象，冻结 Topic 基线以来全部内容、所有 Ticket 验收并集、规则、已决事项；复用四轮上限与四个停止信号，不使用 Ticket 审查替代整分支审查。

多票 complete 校验当前分支 pass、摘要，并重新运行全量测试。测试改变内容也不能归档。有修复内容时只做一次收尾提交；私有模式在元数据提交失败后可以重试，不重复代码提交。branch accept 记录理由/已知问题、accepted 度量与摘要；reopen 必须 Ticket/Spec 稳定定义改变。

abandon 对未归档 Topic 保存原因、元数据和度量，保留未提交内容，输出其路径，归档后不再进入 overview 或实施。

## 验证

9 项 CLI 测试覆盖 shared/private 的单票、多票分支修复、分支接受、放弃；同时覆盖全量空集合/失败/全部命令、验收并集、独立轮数、四轮后失效、停止原因、定义重开、收尾重测失败、测试改变内容及私有归档 hook 失败重试。Ticket accept 的两模式用例见 06。

## 证据边界

本票增强自审，批次完成后另做统一独立审核。当前项目仍使用已安装施工 runtime，产品 v2 行为以临时 Git 仓库 CLI 测试验证；不将施工旧元数据直接迁移成新产品 Topic。无推送或安装，08–14 不在本批范围内。

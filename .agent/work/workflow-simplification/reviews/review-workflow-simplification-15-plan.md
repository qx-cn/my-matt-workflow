# 补偿修复的根因与实施计划

本方案在修改源码前形成并做设计成立性自检。用户明确授权系统性修复三项补审发现；原 Spec r1 足以定义期望，无须修订 Spec 或重开旧完成 Ticket。

| 发现 | 根因 | 最小修正 | 可观察验证 |
| --- | --- | --- | --- |
| CR02-C1 | render 写裸字符串，read 对同一词法值作 JSON 标量推断 | 所有新配置值用 JSON 编码；已知字符串字段的旧裸值按字符串读，结构字段仍解析并严格校验 | setup→overview→再次 setup，保留 reserved-word/数字/转义分支；旧裸值兼容，坏类型仍拒绝 |
| 03-C1 | 将每个声明的 argv 与全历史最后一条成功匹配，丢失批次、声明位置和执行完成性 | 保存最近正式批次的身份、声明 argv 序列、完成标记；每条结果绑定批次与声明位置，完成标记最后写；progress 不替换正式批次；旧记录无证明时重测 | 重复和等价 argv [失败,成功] 仍失败；进度通过不能掩盖；重测恢复；强杀测试 CLI 后不复用旧通过；内容漂移拒绝 |
| IND04-S1 | 不变量编号识别只允许字母前缀，遗漏 Spec 数字编号 | 统一从冻结 Spec 提取数字及字母前缀编号，去重生成唯一 coverage_targets；沿用严格 submit 校验 | I-1…11 与 I-K1/I-T1 全覆盖，漏项拒绝、完整通过、不适用须理由；未知/重复拒绝 |

设计自检：三个修正分别落在既有类型/证据/覆盖校验 seam；不禁止原来合法的重复声明，不用“拒绝 null 分支”规避序列化问题，不放宽 coverage 校验。测试批次持久化发生在执行前，因此失败、中断和内容漂移不能靠旧通过记录恢复通过。旧未分批证据采用 fail-closed 重测，保留原始历史，不猜测完整性。

TDD：先增加公共 CLI 行为回归并确认三类失败；再最小修正；运行三个相关模块，随后按声明执行全量 suite。独立复审绑定 runtime snapshot，继承模型，无实施总结/方案输入。

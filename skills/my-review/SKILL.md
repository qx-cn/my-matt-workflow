# 审查改动

运行 `python3 <本 Skill 目录>/scripts/review_snapshot.py --repo <仓库路径> --base <基准 ref>` 收集 JSON 快照。
范围包括相对基准的已提交改动、已暂存、未暂存、未跟踪文件和嵌套 Git 仓库；遵循各仓库的忽略规则。
快照包含各层 diff 与未跟踪文件内容，可直接交给审查者。二进制内容以 base64 表示。

派一个新上下文的子 Agent，只给它改动快照和 Spec（没有 Spec 时给原始需求），不给实施总结。
审查只报影响正确性或需求的问题，每条附代码位置和具体失败场景。同一根因合并，没有问题就写 `No findings.`。
审查者只读不改。修完之后最多复查一次，仍有问题就如实报告。
派不出子 Agent 时，说明原因并改为自审，不把自审称作独立审查。

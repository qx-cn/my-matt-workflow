# My Writing Great Skills

Skill 的存在，是为了从随机系统中驯服出确定性。根本美德是 **可预测性**：每一次运行采用相同的**过程**，而不是产出相同的结果；下列每个杠杆都服务于它。

**粗体术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中定义；请查阅该文件获得完整含义。

## 调用

两种选择，交换的是不同成本：

- **模型调用**的 Skill 保留**描述**，因此 Agent 能自主触发它，其他 Skill 也能抵达它（你仍可输入其名称）。它带来**上下文负荷**：描述每一轮都占据上下文窗口。机制：省略 `disable-model-invocation`，并写一条面向模型、带有丰富触发措辞的描述（“当用户想要……、提到……时使用”）。
- **用户调用**的 Skill 把描述从 Agent 的触达范围中移除：只有你输入其名称才能调用它，其他 Skill 也无法调用。它没有上下文负荷，却消耗**认知负荷**：由*你*充当记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 转为面向人类的一行摘要，去掉触发列表。

只有当 Agent 必须自行抵达该 Skill，或另一项 Skill 必须抵达它时，才选择模型调用。若它只会由人工触发，就应将其设为用户调用，避免上下文负荷。

当用户调用的 Skill 多到超出你的记忆能力时，堆积的认知负荷可由**路由 Skill**解决：一个用户调用的 Skill，列出其他 Skill 及各自应在何时使用。

## 编写描述

模型调用的**描述**有两项工作：说明 Skill 是什么，并列出应触发它的**分支**。每个字都会增加**上下文负荷**，因此描述比正文更应严格删减：

- **把 Skill 的主导词前置**——描述在此承担调用工作。
- **一个分支只保留一个触发条件。** 把同一分支换个名字的同义说法是**重复**——“使用 TDD 构建功能……要求测试先行开发”是在重复同一个分支。应合并它们；只保留真正不同的分支。
- **删去正文已经具备的身份说明。** 描述仅保留触发条件，以及任何“当另一项 Skill 需要……”的抵达条款。

## 信息层级

Skill 由两类可自由混合的内容构成：**步骤**和**参考**。它可以全是步骤、全是参考，或两者兼具。核心决策是用哪一种，以及每种应在**信息层级**的何处——这是一架按 Agent 对材料的即时需要程度排序的梯子：

1. **Skill 内步骤**——`SKILL.md` 中按顺序执行的动作，是首要层级：Agent 要做什么、按什么顺序做。每一步以**完成条件**结束，即判定工作完成的条件。条件应当*可检查*（Agent 能否区分完成与未完成？）；在重要处还应当*穷尽*（“已说明每一个修改的模型”，而不是“生成变更清单”），因为模糊条件会招致**提前完成**。
2. **Skill 内参考**——`SKILL.md` 中按需查阅的定义、规则或事实。它常常是正当的扁平同级集合（例如一次审查中的所有规则同处一层）——这没有问题，不是坏味道。*本 Skill 全是参考。*
3. **外部参考**——从 `SKILL.md` 推送到单独文件、通过**上下文指针**抵达的参考，只在指针触发时加载。（范围从*已披露*参考——如仍属于该 Skill 的同级 `GLOSSARY.md`——到位于 Skill 系统外、可被任一 Skill 指向的完整**外部参考**。）

要求严格的完成条件会驱动彻底的**基础工作**——Agent 在工作中进行的挖掘——无论 Skill 是否有步骤皆如此；因为“应用每一条规则”对扁平参考的约束，与“完成每一步”对顺序步骤的约束同样有效。

下推得太少，顶层会膨胀；下推得太多，又会隐藏 Agent 实际需要的材料。这种张力正是全部决策所在。

**渐进式披露**是沿梯子向下移动——从 `SKILL.md` 移至链接文件——从而让顶层保持清晰。机制：在 Skill 文件夹中放置一个以内容命名的链接 `.md` 文件（本 Skill 将完整定义披露到 `GLOSSARY.md`）。有些 Skill 有多种用法，每种不同用法都是一个**分支**：不同运行走过其中不同路径。分支是最干净的披露检验：每个分支都需要的内容内联，只有部分分支需要的内容放到指针之后。**上下文指针**的*措辞*而非目标决定 Agent 在何时、以多高可靠性抵达材料。

梯子决定一项内容应当*下放多远*，而**共置**决定它到达该处后*与什么放在一起*：应将一个概念的定义、规则与注意事项置于同一标题下，而非分散各处；如此阅读某一部分就会同时带上邻近内容。

## 何时拆分

**粒度**是划分 Skill 的精细程度，每一次切分都要消耗两类负荷之一，因此只能在切分值得时进行。有两种切分：

- **按调用拆分**——当存在一个应当独自触发的不同**主导词**，或另一项 Skill 必须抵达它时，拆出一个**模型调用**的 Skill。新 Skill 始终加载的**描述**会消耗**上下文负荷**，因此这种独立可达性必须值得付出代价。
- **按序列拆分**——当仍在前方的**步骤**（某一步的**完成后步骤**）会诱使 Agent 仓促完成眼前的一步（**提前完成**）时，拆开一串步骤。让后续步骤离开视野，能促使 Agent 在当前任务上做更多**基础工作**。

## 剪枝

让每层含义保持在**单一事实来源**中：一个权威位置，因此变更行为时只需改一处。

生成计划、Spec 或 Ticket 的 Skill 复用[最终态写作](references/shared/final-state-writing.md)，不重复定义这项规则。

逐行检查**相关性**：它是否仍与该 Skill 的工作有关？

接着逐句搜寻**无效操作**，而非只逐行检查：孤立地对每个句子进行无效操作测试；一个句子未通过时，删除整句而不是仅删几个词。要果断——多数未通过的散文应被删除，而不是改写。

## 主导词

**主导词**是模型预训练中已有的紧凑概念，Agent 在执行 Skill 时会借其思考（例如 *lesson*、*fog of war*、*tracer bullets*）。它会在全文反复出现（但不一定如此——强有力的主导词可能只需一次），累积成分布式定义，并以最少 token 锚定整片行为区域，因为它会调动已有先验。

它以两种方式服务可预测性。在正文中，它锚定**执行**：Agent 每次看到该词，都会抵达相同行为。在描述中，它锚定**调用**：当同一个词出现在你的提示、文档和代码中，Agent 会将这种共享语言与该 Skill 连接起来，更可靠地触发它。

寻找重构 Skill 以采用主导词的机会。在三处完整拼出的三元组（**重复**）、一条描述花一整句指向一个想法——都在等待被**折叠**成单一 token。示例：

- “快速、确定、低开销” -> *tight*——把某一阶段反复表述的一项质量——折叠为一个预训练词（一个 *tight* 循环）。
- “你相信的循环” -> *red*——将模糊的门槛转换为二元、可观察的状态（循环会在 bug 上变为 *red*，或者不会）。

你会赢得两次：token 更少，且 Agent 的思考有了更锐利的挂钩。假设每个 Skill 都藏有能被主导词淘汰的重述——去找出来。

## 失效模式

用它们诊断用户可能遇到的 Skill 问题。

- **提前完成**——在一步真正完成前结束它，注意力滑向了*完成这件事*。按顺序防御：先收紧完成条件（廉价、局部）；仅当条件无法进一步变清晰且确实观察到匆忙时，才通过拆分隐藏完成后步骤（序列切分）。
- **重复**——同一含义存在于多个位置。它消耗维护与 token，并把某个含义在层级中的突出度抬高到超过其真实等级。
- **沉积**——由于添加看似安全、删除看似有风险而沉淀下来的过时层。没有剪枝纪律的任何 Skill 的默认命运。
- **蔓延**——即使每一行都活跃且唯一，Skill 仍然太长。它损害可读性与可维护性并浪费 token。解法是梯子：在指针后披露**参考**，并按**分支**或序列拆分，使每条路径只携带它需要的内容。
- **无效操作**——模型默认已经会遵守的一行，所以你付出负荷却没有传达任何内容。测试是：与默认行为相比，它是否改变了行为？弱主导词（模型已经相当彻底时的 *be thorough*）是无效操作；修复方式是使用更强的词（*relentless*），而不是换一种技巧。
- **否定**——通过禁止来引导会适得其反：*不要想一头大象*会说出大象，让它更容易被想到，而不是更难。应提示**正向**目标——陈述目标行为，使被禁止的行为不被说出；只有在无法正向表述的硬护栏中才保留禁止，即便如此也应与要做什么配对。

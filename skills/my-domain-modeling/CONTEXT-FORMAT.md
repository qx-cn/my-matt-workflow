# 个人术语表格式

默认个人术语表位于 `.agent/work/<topic>/domain/domain-<topic>-glossary.md`。项目已有正式术语表时先读取它；本文件用于记录尚未写回团队文档、或项目未指定正式位置的已解决术语。

## 结构

```md
# {领域上下文名称}

{用一到两句话说明该上下文是什么、为何存在。}

## 语言

**订单**：
{用一到两句话说明该术语。}
_避免使用_：采购、交易

**发票**：
交付后向客户发出的付款请求。
_避免使用_：账单、付款申请

**客户**：
下订单的个人或组织。
_避免使用_：Client、买方、账户
```

## 规则

- **要有取舍。** 同一概念存在多个词时，选出最佳用词，其他词写在 `_避免使用_` 下。
- **定义要紧凑。** 最多一到两句话；定义它**是什么**，而非它做什么。
- **只收录此项目上下文特有的术语。** 即使项目大量使用，通用编程概念（超时、错误类型、工具模式）也不应收录。添加前先问：这是该上下文独有的概念，还是通用编程概念？只有前者属于术语表。
- 自然出现术语簇时，**按子标题分组**；若所有术语属于一个连贯领域，平铺列表即可。

## 单上下文与多上下文仓库

**单一上下文（大多数仓库）：** 使用一个 `.agent/work/<topic>/domain/domain-<topic>-glossary.md`，或项目配置指定的一份正式术语表。

**多个上下文：** 在 `.agent/work/<topic>/domain/domain-<topic>-context-map.md` 维护上下文、位置和它们的关系；若团队已有映射文件，优先读取并遵循团队格式：

```md
# 上下文映射

## 上下文

- [订单](./ordering-glossary.md) — 接收并跟踪客户订单
- [计费](./billing-glossary.md) — 生成发票并处理付款
- [履约](./fulfillment-glossary.md) — 管理仓库拣货和发货

## 关系

- **订单 → 履约**：订单发出 `OrderPlaced` 事件；履约消费该事件并开始拣货
- **履约 → 计费**：履约发出 `ShipmentDispatched` 事件；计费消费该事件并生成发票
- **订单 ↔ 计费**：共享 `CustomerId` 与 `Money` 类型
```

本 Skill 按以下方式判断结构：

- 项目配置或已有团队映射表列出了多个上下文时，先读取它以定位上下文；
- 只有一份正式或个人术语表时，视作单一上下文；
- 两者都没有时，在第一个术语解决后按需创建 `.agent/work/<topic>/domain/domain-<topic>-glossary.md`。

多个上下文并存时，判断当前议题属于哪个上下文；仍不明确时将归属选择分类为 `consequential`，执行 runtime `decision-gate` 的唯一结果，不自行列出多种动作。

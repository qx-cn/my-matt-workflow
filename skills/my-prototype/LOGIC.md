# 逻辑原型

一个极小的交互式终端程序，让用户亲手驱动状态模型。问题涉及**业务逻辑、状态转换或数据形状**时使用——这类事情在纸上看似合理，只有推过真实场景才会暴露问题。

## 适用情形

- “我不确定这个状态机能否处理先 X 后 Y 的边缘情况。”
- “这个数据模型真的能表示……的情形吗？”
- “在实现前，我想感受一下 API 应该是什么样。”
- 任何用户想**按按钮、观察状态变化**的问题。

若问题是“它应该长什么样”，这是错误分支；改用 [UI.md](UI.md)。

## 过程

### 1. 写明问题

写代码前，说明正试验哪个状态模型、要回答什么问题。用一段话写在原型 README 或文件顶端注释中。回答错问题的逻辑原型纯属浪费；问题必须明确，方便此刻查看或用户稍后离线返回时核对。

### 2. 选择语言

使用宿主项目采用的语言。项目没有明显运行时（如纯文档仓库）时，把语言选择视为 `routine` 的可逆原型细节：选用当前环境已有、无需新增依赖的标准库语言，并记录依据；不要为此单独暂停。

匹配项目既有工具约定；不得只为原型增加新的包管理器或运行时。

### 3. 将逻辑隔离为可移植模块

将真正回答问题的逻辑放在一个小而纯的接口之后，使它日后可被取出并放入真实代码库。周边 TUI 是一次性的，但逻辑模块不应如此。

合适形状取决于问题：

- **纯 reducer**：`(state, action) => state`。动作是离散事件、状态是单个值时适合。
- **状态机**：显式状态与转换。当“此时哪些动作合法”正是问题的一部分时适合。
- **围绕普通数据类型的一组纯函数**：没有隐含当前状态，只有转换时适合。
- **方法面清晰的类或模块**：逻辑确实拥有持续的内部状态时适合。

选择最符合问题的形状，**而不是**最容易接到 TUI 的形状。保持纯粹：不做 I/O，不写终端代码，不用 `console.log` 控制流程。TUI 导入并调用逻辑；不得反向依赖。

这使原型在生命周期后仍有价值：问题解决后，已验证的 reducer、状态机或函数集可以独立提取到真实模块。

### 4. 构建展示状态的最小 TUI

构建**轻量 TUI**：每一轮清屏（`console.clear()` / `print("\\033[2J\\033[H")` 或等效方式），再重新渲染完整画面。用户应始终看到一个稳定视图，而不是不断增长的滚屏。

每一帧按此顺序包含两部分：

1. **当前状态**：格式化且便于 diff（每行一个字段，或格式化 JSON）。字段名或章节标题用**粗体**，不重要上下文（时间戳、ID、派生值）用**暗色**。可直接用 ANSI 转义码：`\\x1b[1m` 粗体、`\\x1b[2m` 暗色、`\\x1b[0m` 重置；除非项目已有依赖，否则无需引入样式库。
2. **快捷键**：在底部列出，例如 `[a] 添加用户  [d] 删除用户  [t] 推进时钟  [q] 退出`。可加粗按键、淡化说明，或反过来；以清晰为准。

行为：

1. **初始化状态**：一个内存对象 / struct；启动时渲染第一帧。
2. 每次读取一个按键（或一行输入），分派给修改状态的处理器。
3. 每次动作后**重新渲染**整帧，不追加内容而是替换。
4. 循环到退出为止。

完整画面应能放进一屏。

### 5. 保证一条命令可运行

在项目现有任务运行器中添加脚本（`package.json` scripts、`Makefile`、`justfile`、`pyproject.toml`），仅在项目策略已允许修改这些团队文件时执行。用户应运行 `pnpm run <prototype-name>` 或等效命令，而不必记住路径。

宿主项目没有任务运行器时，把命令写在原型 README 顶部。

### 6. 交给用户

提供运行命令。用户会亲自驱动它；有意思的时刻是他们说“等等，这不应该能发生”或“咦，我以为 X 会不同”——那是**想法**中的 Bug，正是原型的目的。若需要增加动作就增加，原型会演化。

### 7. 捕获结论和原型

原型回答问题后，先捕获答案，再按 [SKILL.md](SKILL.md) 所述捕获原型。逻辑专属映射为：已验证的 reducer、状态机或函数集进入真实模块（决定被吸收）；TUI 外壳仍是一次性工件，保留在 `.agent/work/<feature>/prototypes/`。如项目策略批准保存一手证据，可将外壳放入一次性分支；不得自动创建分支或 Commit。

## 反模式

- **不要增加测试。** 需要测试的原型已经不再是原型。
- **不要接真实数据库。** 除非问题专门针对持久化，否则使用内存存储。
- **不要泛化。** 不问“以后要支持 X 怎么办”。一个原型只回答一个问题。
- **不要把逻辑与 TUI 混在一起。** 若 reducer / 状态机引用 `console.log`、提示或终端转义码，它就不再可移植。TUI 必须是纯模块上的薄壳。
- **不要把 TUI 外壳投入生产。** 外壳针对手动终端驱动而优化；真正值得保留的是背后的逻辑模块。

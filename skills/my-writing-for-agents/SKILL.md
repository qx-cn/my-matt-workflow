# 为 Agent 编写指令

适用于 Skill、AGENTS.md、CLAUDE.md。默认动作是删除：逐句保留会改变目标 Agent 必要行为的内容，先去掉过时、重复、可自行查证及模型默认能力已覆盖的句子，再判断是否需要改写。静态文字审查只能证明结构与可解析性，行为增益的证据边界由 my-review-instructions 判断。

## 指针与调用

Skill 描述，以及 AGENTS.md 中指向某份文档的那一行，都是上下文指针。先写熟悉的关键词和目标，再写需要读取的情形；每种情形只保留一个触发条件，删除正文已有的身份信息。例如“迁移数据库时读取 migration.md 的回滚约束”，将触发与目标放在同一行。

只有 Agent 或其他 Skill 需要触发时才设置模型调用；权限以组合清单及[宿主投影](references/shared/adapters/composition.md)为准。两个手动 Skill 共用的内容放普通文件。手动入口多时用路由 Skill 索引，让人只在需要判断的地方记住入口。

完成条件：每个指针都能判断何时读、读来做什么；调用方式与真实消费者匹配。

## 信息负担与分层

常驻内容带来上下文负担；让人记住哪些文档存在带来认知负担。认知负担只花在需要人判断的地方。

区分文件内步骤、文件内参考、外置参考。所有情形都要用的内容留在文件内，只有部分情形需要的放外置参考并写触发指针。同一概念的定义、规则与注意事项集中；过长时按情形或按顺序拆分，不让每条路径携带无关材料。

完成条件：每份材料都有明确读取情形，每个意思只有一个定义位置。

## 完成条件与表达

每一步以可判定的完成条件结束，先写清条件。例如“每项验收已关联独立测试证据”比“理解验收”可判定。只有条件确实写不清、且已观察到提前收工时，才把后续步骤拆到新上下文；单纯变长或担心匆忙不足以拆分。

用模型熟悉的概念词作关键词，如 tracer bullet、red/green；尽量表达正向目标。只有无法正向表达的硬约束才用禁令，同时给出要达到的目标。

完成条件：Agent 能区分完成与未完成；每个硬约束有明确目标，拆分有实际依据。

## 剪枝交付

逐句检查相关性与必要行为贡献。环境可查的事实交给查证，模型默认会做的事整句删除，重复规则改为指向唯一来源。只有仍影响触发、动作或完成度时才保留。

完成条件：交付保留、删除或改写的具体依据；未知保持未知，静态检查不写成模型效果已验证。需要诊断术语时再读 [GLOSSARY.md](GLOSSARY.md)。

# 架构候选前端阶段

只把 `content-ready` 的 `architecture-review` 语义工件渲染为临时自包含 HTML。不得重新扫描代码库，也不得改变候选顺序、推荐强度、事实或结论。

检查必填字段、每个候选的证据/收益/成本/风险，以及首要推荐。承重信息缺失时返回 `blocked-by-content`。

按 [HTML-REPORT.md](HTML-REPORT.md) 渲染：

- 内联 CSS；只有语义工件要求时使用内联 SVG；不加载 CDN 或远程脚本。
- 每个候选有可定位卡片，包含模块/文件、问题、深化方向、收益、成本/风险和推荐强度。
- 只实现语义工件里的 `visual_intent`；没有意图时不造装饰图。
- 报告末尾突出首要推荐及理由。

实际打开文件，检查宽屏和窄屏阅读、文字溢出、颜色对比、链接与离线可用性。完成后报告 HTML 与语义工件绝对路径，再问用户要深入哪个候选。

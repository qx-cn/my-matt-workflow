# 技术方案前端阶段

只负责把 `content-ready` 语义工件渲染为可评审 HTML。语义工件是内容权威来源；不得新增、删除、合并或改写其中的事实、结论、约束、未知和章节含义。

## 准入

检查 frontmatter 必填字段、来源引用、输出路径、章节 `section_id`、改动面追踪和未知项。若某节缺少可渲染内容或视觉意图缺少节点/关系，返回 `blocked-by-content`；不要回到代码库猜答案。

## 渲染

复制并填写 [HTML 模板](assets/TEMPLATE.html)，保留离线导航、动态章节切换、折叠、页底评审注释、本地保存与 Markdown 导出。只在语义工件确实需要时增加交互。

- 按章节生成 `{{NAV_ITEMS}}` 与 `{{CHAPTER_SECTIONS}}`，删除全部剩余占位符。
- 承重决策确实需要快速定位时才使用 `decision-strip` 或 `decision-index`，不生成空卡片。
- 密集表格和长列表使用整行卡片；两栏只用于短内容，空间不足时改为上下排列。
- 成对比较使用 `comparison` / `comparison-card`，每侧有标题和列表。
- CSS、JavaScript、SVG 全部内联，不加载远程资源。

仅实现语义工件中的 `visual_intent`。结构与依赖用关系图，步骤和分支用流程图，跨模块先后用时序图，状态变化用状态图，实体关系用 ER 图；若渲染时发现表格更清楚，可在不改变信息含义的前提下改用表格，并记录这一呈现选择。关键结论仍以文字呈现。

## 视觉验收

运行 `python3 scripts/check_html.py <html>` 并处理错误，逐项复核术语警告。实际渲染每个章节，至少检查 1440px 和 1280px：无裁剪、重叠、逐字换行或意外横向滚动；离线导航、折叠、保存与 Markdown 导出可用。

最后对照语义工件逐项检查可见主张与章节顺序。报告 HTML 和语义工件路径、检查过的宽度与未验证项。

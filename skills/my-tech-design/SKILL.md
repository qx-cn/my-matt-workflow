# 技术方案

给工程师判断方案是否成立，不是实现清单。
阅读已有需求、Spec、决定和相关代码。现状描述附代码依据，无法确认的内容写为已知限制。
结论先行，说明关键选择、理由、代价和风险。章节随实际改动组织，不锁定普通实现细节。

按改动涉及的对象说明接口与数据契约、存量数据处理、并发与锁、兼容、上线顺序和回滚边界。
读者需要判断的实际接口、消息、配置或数据定义集中呈现一次，其他地方引用它。
如果读者不能访问 Spec，将判断方案所需的约束和依据写全。

选择能降低读者理解成本的文字、表格或图示，简单内容无需图示。关键规则仍用文字说明。
密集表格和长列表用整行区域，两栏用于短内容。成对比较可用模板的 comparison / comparison-card，每侧有标题和列表。

用 `assets/TEMPLATE.html` 生成 `.agent/work/<主题>/design.html`。
填写标题、总览和章节占位符，导航与章节 ID 对应；不用的可选区块直接去掉。
保留离线导航、折叠、页底评论、本地保存和 Markdown 导出。CSS、JavaScript 和 SVG 内联。
运行 `python3 <本 Skill 目录>/scripts/check_html.py .agent/work/<主题>/design.html`，处理错误并复核警告。
在可用的浏览器中核对布局和交互；未验证的部分如实说明。

发布到飞书时只更新改动过的章节，保留已有评论。工具做不到就停下来说明。

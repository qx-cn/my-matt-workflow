# 技术方案与发布文档

依据已有需求、Spec、`decided.md` 和代码事实编写；现状描述附代码依据，无法确认的列入待确认项或遗留项。

## 1. 确认文档类型与输出载体

动笔前先明确以下两项：

- **文档类型**：默认写**技术方案**；用户提到"发布文档 / 上线文档 / 发布方案"或给出发布文档链接时写**发布文档**。按类型读取 [TEMPLATES.md](TEMPLATES.md) 中对应章节。
- **输出载体**：支持**飞书云文档**或**本地 HTML**。用户未明确指定载体（也没给飞书链接/目录）时，**先问用户要飞书文档还是本地 HTML**，不默认生成 HTML。

## 2. 内容与排版原则

正文组织与排版遵循以下约束：

- **范围与重点**：只写本项目负责、新增或改变的部分。以读者熟悉的现有机制为参照，一句话交代复用了什么，重点标出本次与现状的差异点；不展开下游服务实现和未修改的公共协议/代码。
- **章节组织**：围绕本项目核心问题组织并放在显眼位置（如报表的"字段与数据来源"、接口的"接口契约"）；没有实际内容的章节整节省略，不写"无"。同一结论只在一处展开，不在总览、正文和表格之间重复叙述，也不在表格外把表内各行再念一遍。
- **标题与表格**：标题用中文业务概念而不塞函数名或字段名，每个标题下先写至少一句总括说明（不标题直接套标题），只有一个子项时不拆子标题，三级标题以下用缩进列表代替四级标题；简单的"名称：说明"二元组用列表，三列及以上多属性对比用表格，单元格不超过两句话（长说明拆到表外列表）。
- **代码与定义**：尚未编码时用流程、表结构或协议说明设计，不虚构未实现的函数做代码对比；数据与接口变更只贴新增或修改的 Proto、DDL、SQL、MQ、配置片段（代码注释只写非直觉的业务约束与原因，不复述字面意思），定义只在一处出现。
- **图表**：只在能明显降低理解成本时使用；每张图只表达一个核心流程或关系（复杂系统拆成总览与子图），图旁配一句结论说明读者该看什么，节点只放短标签。

## 3. 按载体输出

根据第 1 节确认的载体执行对应流程：

### 飞书云文档
调用 `lark-doc` 技能操作：
- **新建**：在用户指定的飞书知识库节点或目录下创建，按 [TEMPLATES.md](TEMPLATES.md) 组织结构并按第 2 节原则裁剪。
- **更新已有文档**：只更新有改动的章节，保留未改章节与已有评论；工具做不到章节级更新时停下说明，不整篇替换。

### 本地 HTML
按以下步骤生成并校验本地文件：
- 用 `assets/TEMPLATE.html` 生成 `.agent/work/<主题>/design.html`：填写标题、总览和章节占位符，导航与章节 ID 一一对应，不用的可选区块删掉。保留离线导航、折叠、页底评论、本地保存和 Markdown 导出；CSS、JavaScript、SVG 内联。
- 密集表格和长列表用整行区域，两栏只放短内容。成对比较用模板的 comparison / comparison-card，每侧有标题和列表。
- 运行 `python3 <本 Skill 目录>/scripts/check_html.py .agent/work/<主题>/design.html`，修完所有错误；有可用浏览器时核对布局和交互，未验证的部分如实说明。

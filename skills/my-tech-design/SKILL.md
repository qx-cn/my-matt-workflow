# 技术方案与发布文档

依据已有需求、已有的 `.agent/work/<主题>/spec.md`、`decided.md`、`refs/`（存在时读取）和代码事实编写，遵守全局写作规范。现状描述与恢复命令须经代码核实，无法确认的事项列入待确认项或遗留项；来源材料含义冲突时先澄清，不自行按文件类型定优先级。

若当前会话已积累大量源码排查或长访谈记录，可派干净上下文的子 Agent（传入原始需求或已有的 `spec.md`、已有的 `decided.md` 与 `refs/`、待核实的源码位置，以及全局写作规范、本 Skill 与 [TEMPLATES.md](TEMPLATES.md)）生成方案初稿，隔离前序对话中的排查噪音。

## 1. 确认文档类型与输出载体

动笔前先明确以下两项：

- **文档类型**：默认写**技术方案**；用户提到"发布文档 / 上线文档 / 发布方案"或给出发布文档链接时写**发布文档**。按类型读取 [TEMPLATES.md](TEMPLATES.md) 中对应章节。
- **输出载体**：支持**飞书云文档**或**本地 HTML**。用户未明确指定载体（也没给飞书链接/目录）时，**先问用户要飞书文档还是本地 HTML**，不默认生成 HTML。

## 2. 内容与排版原则

初写、缩减和润色均适用以下约束：

- **受众与主次（面向人类评审人）**：
  - **剥离施工级噪音**：正文写服务、模块、接口与表字段，不贴函数内部源码路径与行号（如 `.go:168`），全量同名直拷字段清单留给 `spec.md` 或外部映射表链接；尚未编码时用流程、表结构或协议说明设计，不虚构未实现的函数做代码对比。数据与接口变更只贴新增或修改的核心 Proto、DDL、SQL、MQ、配置片段，同一定义只出现一次，注释只解释非直觉的业务约束与原因。
  - **核心痛点置顶，排除项归入取舍**：把触发本次改动的根本业务问题放在第一位讲清；调研期评估过但未采用的候选方案只在方案选型处简述排除原因，不把备选方案的缺陷当成现网系统的痛点。
  - **改动边界清晰**：标清本次修改的模块与直接复用的既有机制（未改动的既有事务、锁、幂等在此处一句话带过，不单独列大表）；仅当存在评审人合理预期可能包含但决定延后或另案处理的事项时才列为边界，不拿无关项凑“本次不做”。
- **可理解性与可操作性（不跳步）**：
  - **按逻辑层次拆列表**：单条列表项只讲一层意思；当包含判定条件、原因分析与执行步骤等多层信息时，拆分为嵌套子列表（`<ul>/<ol>`），既避免将多层逻辑塞进同一自然段形成纯文本段落墙，也不因压缩字数而省略关键判据与原因。只有一个子项时不拆子标题，四级及更深层级用缩进列表。
  - **回滚与异常恢复可执行**：按实际风险分配篇幅；回滚方案分开说明**服务版本回滚**与**异常数据/状态恢复**，核实运行期已产生的状态或数据变更能否随镜像自动恢复；需工具或人工恢复时，核实代码行为并写明可查验的状态判据与工具组合原因（如：`❌ 对未处理（WAITING）任务跑恢复脚本` → `✅ 对 task_table.status = 'waiting' 的任务执行重放命令，对 status = 'completed' 的任务先重置状态再重放`）。
- **信息形态路由与视觉排版（按内容复杂度选用）**：
  - **文首方案总览**：技术方案文首固定提供简明的高亮`方案总览`（`1. 背景与问题`、`2. 核心方案`；本地 HTML 模板额外含`关键风险与边界`卡片），供评审人快速把握全局。
  - **按信息关系选载体**：
    - 多维枚举或字典映射使用独立表格，按分类逐行展示，不在正文串写映射或在单格内混塞多类；
    - 复杂的新旧流程对比、成对分支或核对/排除范围优先使用双栏并排对照（飞书 `<grid>` + `<callout>`，HTML `.comparison` + `.comparison-card`），简单直观处不强行凑双栏；
    - 表格单元格保持简短，长篇原因或步骤推理移到表外列表。
  - **以图代字与画板防崩护栏**：当跨时间/阶段状态变化、分支流向或跨环境验证架构用文字难以一眼看清时，拆为 1 到 3 张聚焦图示（跨阶段新旧表现对比优先采用“顶部阶段列 + 上下新旧泳道行”二维对比图；本地 HTML 用内联 SVG，飞书用画板；简单改动不强行凑图），**图下正文不重复复述图内已画清的过程**。飞书画板按图表类型分流，避免手写 SVG 转画板产生窄文本折行重叠：
    - **格式选型**：时序图等标准代码图可用 Mermaid；二维对比泳道、分支流程与架构图优先使用 `lark-whiteboard` 的 JSON DSL。
    - **容器与文本**：容器 `frame` 显式声明 `layout` 与 `padding`；含文字的 `rect` 设足够宽度、`height: "fit-content"` 并将文字内嵌于 `rect.text`。
    - **拓扑与连线**：复杂分支或跨环境架构拓扑使用 `layout: "dagre"` 配合根级 `layoutOptions.edges`（不叠加顶层 `connector`）；二维泳道或规整单线流程使用 Flex（`horizontal` / `vertical`），带连线的主轴容器设 `gap >= 40`（无连线的外层泳道行或对比行保持 `12` 至 `24` 紧凑间距），顶层 `nodes` 中的 `connector` 按节点相对位置显式指定 `fromAnchor` 与 `toAnchor`（横向用 `"right" -> "left"`，纵向用 `"bottom" -> "top"`，不省略锚点以免斜线穿框）。
- **改写核对与真实链接**：缩减或润色后对照来源和前稿，核对受影响的对象、条件、动作与唯一约束未丢失；篇幅与必要内容冲突时说明并请求取舍。文末参考资料填入可点击的真实 URL 链接，不写无链接的本地文件名。

输出前核对实际交付版本；语法校验不替代内容核对。独立审查由用户按需显式调用，不因每次生成或微调自动启动子 Agent 审查。

## 3. 按载体输出

根据第 1 节确认的载体执行对应流程：

### 飞书云文档

调用 `lark-doc` 与 `lark-whiteboard` 技能操作：

- **新建文档**：若目标飞书目录或知识库节点下已有团队近期技术方案，先读取 1 篇对齐排版与颗粒度；再按 [TEMPLATES.md](TEMPLATES.md) 组织结构并按第 2 节原则裁剪创建，主动运用 `<callout>`、`<grid>`、`<span background-color="..." text-color="...">` 与表格底色增强视觉可读性（XML 顶层以 `<title>` 开头，行内代码用 `<code>` 而非反引号）。
- **插入、更新与自检画板**：
  - 新建画板时，正文中先写 `<whiteboard type="blank"></whiteboard>` 占位，取创建或局部增补返回的画板 token，按 `lark-whiteboard` 技能编译并写入内容（JSON DSL 先经 `@larksuite/whiteboard-cli` 编译为原生画板节点格式再覆盖写入，时序图等可直接按 Mermaid 格式写入）。
  - 更新已有文档中的画板时，先读取文档提取既有 `<whiteboard token="..."/>` 复用原画板 token，不重复插入空白画板。
  - 写入后按 `lark-whiteboard` 技能导出预览图读取自检，确认无文字折行重叠、无斜穿框体且未残留空白画板。
- **更新已有文档**：只更新有改动的章节，保留未改章节与已有评论；工具做不到章节级更新时停下说明，不整篇替换。响应评论补充多条原因或步骤时，拆分为子列表或双栏块，不往原长句内硬塞从句。

### 本地 HTML

按以下步骤生成并校验本地文件：

- 用 `assets/TEMPLATE.html` 生成 `.agent/work/<主题>/design.html`：填写标题、总览（`{{WHY}}`、`{{HOW}}`、`{{TOP_RISK}}` 填入 `<p>` 或 `<ul>` 块级内容）和章节占位符，导航与章节 ID 一一对应，不用的可选区块删掉。保留离线导航、折叠、页底评论、本地保存和 Markdown 导出；CSS、JavaScript、SVG 内联。
- 密集表格和长列表用整行区域，两栏只放短内容。成对比较用模板的 `.comparison` / `.comparison-card`，每侧有标题和列表。
- 运行 `python3 <本 Skill 目录>/scripts/check_html.py .agent/work/<主题>/design.html`，修完所有错误；有可用浏览器时核对布局和交互，未验证的部分如实说明。

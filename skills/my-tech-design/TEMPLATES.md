## 一、技术方案

用于评审方案是否成立、风险是否可控。

### 推荐骨架
1. **需求概述**：背景、PRD 链接、目标与不做的范围、本服务职责与上下游分工（必要时附新引入的名词术语表）。
2. **核心方案设计**（围绕本项目核心问题命名和展开）：
   - 系统位置与整体逻辑/流程（复杂时配流程图或时序图，标注与现状的差异点）。
   - 核心问题拆解：如报表项目的"报表字段与数据来源表 + 取值/格式化例子"、业务模型变更、状态机、幂等与并发锁、事务与失败重试恢复。
   - 备选方案与取舍（有真实权衡时写）。
3. **数据与接口变更**（只贴新增或修改的定义片段，附简短用途说明，不贴未改动字段）：
   - 对外协议 / RPC / HTTP / 消息通道与 Payload
   - 存储变更：MySQL 表结构（DDL）与索引变更、ES / Kafka / 大数据 / 配置项
4. **兼容、通用性与灰度**（按实际风险写，涉及数据迁移、兼容或不可逆操作时必须说明回滚）：
   - **数据与调度兼容**：新增字段旧数据为空如何兼容、是否需回填；**Temporal 调度函数签名若变更，如何兼容在途未完成 workflow**（避免发布前创建的 workflow 卡死超时）。
   - **功能通用性**：是否支持多主体（如 `accounting_entity` 维度配置，对 MFI/MCI 等其他主体有无影响）、多品类（正股/期权/数字币等），拒绝无必要的临时硬编码方案。
   - **灰度、上线顺序与回滚**：上下游依赖顺序、灰度维度（按日期/UID/主体）、回滚触发条件与不可逆边界。
   - **监控与容量**（有变化时写）：QPS/存储容量评估；批处理任务关注"数据非 0 + 同比波动"，实时流量关注"分支上报"。
5. **待确认项与参考资料**：影响方案判断的未决问题（怎么确认、找谁确认）；PRD 与关联文档链接。

## 二、发布文档

用于上线交付、变更评审与执行核对。章节结构保持完整，按实际改动填写：

1. **需求描述**：Project 需求单链接 + 一两句话概述需求。
2. **方案设计**：贴技术方案文档链接。
3. **代码改动**：简要说明改动点 + 贴 MR 链接。
4. **影响范围、风险评估、监控指标**：
   - 按四维表格梳理**影响点 / 风险说明 / 监控与告警指标**：
     - **功能**：影响哪些功能、有无风险。
     - **数据**：① 历史数据与代码兼容性；② 新代码读旧数据是否兼容；③ 旧代码读新数据是否兼容；④ 产生新数据后能否回滚。
     - **主体维度**：MCI 主体、MFI 主体（及其他涉及主体）分别受何影响。
     - **外部影响**：是否对上下游产生额外流量或依赖。
   - **监控指标**：批处理关注数据非 0、同比波动；实时流量关注分支上报。
5. **测试用例**：测试覆盖范围说明或思维导图。
6. **测试报告**：
   - 团队验证红线（适用时必须说明）：
     - **实时读接口**：进行 FRecord 回放测试，新旧版本返回差异须明确解释。
     - **实时写接口**：写操作前读取全部字段 → 执行写 → 写后再次读取全部字段 → 逐字段比对，确保只有目标字段变更、其他字段未被篡改。
     - **影响账本或报表数据准确性的修改**：在预发布/镜像/灰度环境进行至少 N 个交易日的双跑验证或历史数据回归（明确 N 的取值与理由），**必须全量比对，不允许仅抽样比对**，差异须明确解释。
   - 自测结果表：`功能点 | 测试场景（成功/异常）| 测试用例（单测/ftest链接）| 测试结果 | 说明/截图`。
7. **性能分析**：新服务评估流量/容量/内存/压测结论；常规迭代说明流量变化（无影响可简写）。
8. **发布前 Checklist**：
   - 基础资源：DB 表/权限、Kafka 资源、服务鉴权/授权、上下游依赖就绪。
   - 常见踩坑核对（涉及对应组件时必查）：
     - 使用 `distributedlock` 或 `mq` 组件：是否建好 `locker` / `record` 表，**是否申请了 delete 权限**；开启 SASL 且用 requeue 时，SASL 是否配在集群维度而非 consumer 维度。
     - 提供或调用 FNS：是否开启 FNS、寻址规则是否已验证。
     - 配置文件中是否残留测试环境硬编码（如 `test_xxx:port`）。
9. **灰度计划、回滚预案、发布后验证**：
   - 按阶段（如 MFI 发布、MCI 发布、补历史数据 SQL）列出表格：`阶段 | 日期与时间段（是否需避开特定时段）| 发布任务（部署组/流量比例/SQL）| 回滚方案/回滚SQL | 发布后验证（日志/监控/手动/灰度流量/跨PD观察）| 验证结果`。
10. **遗留项 & 发布记录**：后续需跟进的资源回收、表结构清理等；发布过程异常记录。

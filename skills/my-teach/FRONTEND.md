# 教学前端阶段

只把 `content-ready` 的课程或参考资料语义工件渲染为 HTML，不改变教学事实、顺序、来源、练习答案、反馈标准或掌握结论。

## 准入

检查学习收获、章节顺序、术语首次解释、来源、练习与答案/评分标准。承重内容缺失时返回 `blocked-by-content`，指出对应 `section_id`，不得自行补课。若结构、流程、跨角色协作或状态迁移被明显错误地标为 `visual_intent: none`，也返回 `blocked-by-content` 并指出 `section_id`，不得自行补造关系或教学事实。

## 渲染

- 课程写入 `lessons/0001-<dash-case-name>.html` 并递增编号；参考资料写入 `reference/*.html`。不覆盖历史，除非任务明确是修订既有文件。
- 课程独立完整、可打印，并用 HTML 锚点链接相关课程和参考资料。
- 课程从 [HTML 模板](assets/TEMPLATE.html) 开始，使用配套的 `assets/course.css` 与 `assets/course.js`，不要每次重新发明布局和组件。工作区缺少这些资产时复制进去；已有同名资产时先检查兼容性，只在明确修订共享呈现时更新并报告可能影响的既有课程。课程特有内容留在 HTML，共享样式与行为留在资产中。
- 实现语义工件中每个非 `none` 的 `visual_intent`，使用原生 SVG 或已有页面组件；多项精确对照可用表格。每张图只回答一个问题并紧邻对应文字结论，图示不能成为关键规则或答案的唯一载体。不得用一排视觉相同、缺少连线方向或交互顺序的 CSS 盒子冒充架构图或时序图。
- 交互只服务于练习反馈或导航；键盘可用，答案不由样式泄露，打印版仍可理解。

### 表达调整

前端可以为阅读体验调整表达形式：拆分或合并段落、把并列信息转成列表或表格、为卡片增加短标题、缩短导航标签，以及把结论移到同一章节更容易看见的位置。调整后必须保留面向读者的事实、因果、限制、反例、来源归属、练习答案和评分标准；不得用短标题替代完整解释，不得跨章节改变理解依赖，也不得加入语义工件没有的新教学结论。作者研究缺口不进入课页，不算内容缺失；影响读者判断的限度必须改写成正文限制或“现场还要核什么”。

### 阅读节奏

- 所有正文保持在同一条连续文档流中。不得增加阅读模式切换、分页按钮、轮播、整页隐藏或 hash 驱动的单页替换；浏览器搜索和锚点应直接作用于全文。
- 首屏使用 `lesson-hero`，让单一学习收获成为最明确的信息；时长、课号和少量术语是辅助信息，不能与学习收获争夺注意力。模板中的 `LEARNER_SUPPORTING_CONTENT` 只可放帮助理解学习收获的学习者内容。hero 和 `main` 开头不得插入证据边界、来源基线、可证明范围、仍需验证或其他制作状态。
- 每个语义章节使用带原 `section_id` 的 `lesson-section`，并生成简短的锚点导航。章节之间用留白、边界和标题建立分页感，不强制每节等高，也不把一节压进一个视口。
- 学习收获、术语首次解释、单个模型或对比、单步例子、一道练习与反馈、常见误解可使用 `focus-card`，让当前知识点在视觉上占主导。卡片只包住一个理解任务，不给每段文字套卡片。
- 因果链、适用边界、代码或状态对照、现实任务迁移使用 `prose-flow`、整行表格或相邻的连续区块；不为卡片整齐而截断论述。来源只放页脚或在相关正文中自然归属，不做来源基线或制作看板。
- 图示紧邻它解释的文字结论。宽表格和图示可在自身容器内横向滚动，页面本身不得产生横向滚动。
- 练习保持题目、作答、即时反馈和答案解释为一个可定位区块；每道交互题在 HTML 中写入 `print-answer` 的正确答案与解释，屏幕作答前不显示、打印时直接显示。不要把正确答案仅放在颜色、图形、`data-*` 或脚本状态中。

参考资料沿用相同排版语言，但不强行使用课程首屏、进度导航或练习组件。

课页使用读者第二人称或中性祈使，例如“用自己的话回答”“对照参考答案”“现场核配置”。不得出现制作方自称、向下一个模型交接、要求 Agent 评分，或“语义工件”“内容修订”“模型隔离”“本课可证明”“来源基线”“待制作”“给 Agent 的出口题”等制作措辞。“事实与结论”“必要关系”“本课仍未知”不得作为对齐工件的固定栏目；内容确有复习价值时改成读者标题。专题首页同样只说明“怎么学”，不展示学习状态、来源基线、待制作或初稿进度。

## 验收

先运行 `python3 scripts/check_html.py <html>` 处理机械结构错误，再实际渲染并检查至少一个桌面宽度、390px 窄屏和打印预览；确认无溢出、遮挡、不可读对比、失效锚点或被隐藏的正文，键盘练习可用，打印包含答案解释与来源。

最后由 Agent 同时阅读语义工件与成品 HTML，按章节逐项核对：学习收获是否一致；读者能读到的事实、因果、限制、反例是否仍在；术语首次解释是否完整；示例的数字与结论是否对应；练习、答案、反馈和评分标准是否一致；来源链接与归属是否改变；所有非 `none` 图示是否实现且未成为唯一信息载体；表达调整是否引入新结论或破坏理解顺序。不要核对交接字段或内部标题是否出现在 HTML；作者研究缺口未进入课页是正确分流，不算内容缺失。发现问题就修正 HTML 并重新复核，不能用“版式需要”解释读者内容缺失。报告内容工件、HTML、复用/新增资产、最终一致性校验结论、检查过的视图和未验证项；这些制作状态只在 Agent 对话中报告。

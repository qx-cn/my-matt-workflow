# 教学内容阶段

只负责准确教学、课程结构和语义工件，不生成 HTML、CSS、SVG 或 JavaScript。

## 准入与定位

先读 `MISSION.md`。缺失，或学习者类型（初学者/已有基础）、现实学习任务、当前能力证据、成功标准不清楚时，一次只问会改变教学路径的问题。用 `learning-records/` 区分“讲过”和“已掌握”，据此选择最近发展区。

读取 `RESOURCES.md` 并补齐本次学习收获所需的一手资料、当前版本文档或公认专家来源。事实、代码和练习答案必须可由来源或可运行示例复核；无法确认时标为未知，不凭模型记忆补写。

## 设计学习收获

每节课聚焦一个与现实任务直接相关、可验证的学习收获。深度以学习者能解释原理、迁移知识并完成真实任务为准，不以篇幅短为目标。

按需要递进：

1. 建立心智模型与必要前置知识；
2. 引导练习，提供紧密、尽可能即时的反馈；
3. 迁移练习，改变表面情境；
4. 真实任务，检验是否能独立应用。

练习必须来自可信的真实场景，有明确练习价值、正确答案或评估标准。用检索、间隔与合适的交错练习制造有益困难，但不要把排版、术语障碍或猜题当难度。测验选项尽量避免长度和格式泄露答案。

## 初学者可读性

关键概念首次出现时按“中文名（英文全称，缩写）→ 白话含义 → 当前案例中解决什么问题”解释。高风险概念说明它不是什么。使用“具体案例 → 发生了什么 → 为什么 → 标准术语 → 系统字段/状态/代码含义”搭桥；标题、练习和反馈不得把未解释术语当作前提。

一句话同时引入新概念、结论和例外时拆开。保留因果、限制、反例和自然过渡，不用口号、反问或故作深刻的标题替代解释。

## 语义工件

按共享交接格式设置 `document_kind: lesson` 或 `reference`、递增课程编号、输出路径与现有共享样式引用。正文至少包含：

- 学习者与用途、单一学习收获、先备知识；
- 结论与来源账本，事实/示例/正确答案的对应来源；
- 按顺序的章节，每节有 `section_id`、教学目标、正文、示例和必要的 `visual_intent`；
- 练习、正确答案或评分标准、反馈、常见误解；
- 与现实任务的迁移步骤、掌握证据和仍未知内容；
- 需要更新的 `reference/`、`GLOSSARY.md` 或学习记录建议。

只有图示能明显澄清流程、结构或因果时才写 `visual_intent`。内容完成后，可用当前环境已安装的 `humanizer` embedded mode 编辑自然语言；保留事实、数字、来源、代码、公式、字段、链接、术语和答案，不新增事实，也不把解释压短到难懂。

保存前从开头随机阅读：学习者无需跳转即可理解首次出现的关键术语，并能回答“发生了什么、为什么、例子是什么、怎样用于现实任务”。

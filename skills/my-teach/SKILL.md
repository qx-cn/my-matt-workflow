用户正在跨多个会话学习一个主题。把当前目录视为持久的教学工作区，并让每一步教学服务于用户的现实学习任务。

## 选择教学工作区

- 默认当前目录就是单主题工作区。
- 有 `topics/` 时，根目录是多主题仓库，实际工作区是 `topics/<topic-slug>/`；若已在该目录中，直接使用它。
- 在多主题根目录：用户指定已有主题时使用它；明确提出新主题时，先确认学习目的，再创建 dash-case 目录；只说“继续学习”时列出主题并请用户选择，不能猜测。
- 选定后，以下所有相对路径都指向该主题工作区；每个主题独立维护任务、资源、课程编号、参考资料、组件和学习记录。旧版根级 `MISSION.md` 仅在用户明确要求后迁移，并先确认方案。

## 教学状态与资料

- `MISSION.md` 记录学习原因、成功标准、约束与范围外内容。先读它；缺失或学习任务不清楚时，先问用户为什么要学，再写课程。格式见 [MISSION-FORMAT.md](./MISSION-FORMAT.md)。改变学习任务前必须取得用户确认，并记录这一变化。
- `RESOURCES.md` 是可信知识来源与实践社区的清单，格式见 [RESOURCES-FORMAT.md](./RESOURCES-FORMAT.md)。先用高质量、一手或公认专家来源建立知识基础，不把参数化知识当作证据；当前收获所需来源不足时先补资源，不用猜测补课。每节课链接其主要来源，并为事实主张保留可追溯引用。
- `learning-records/` 记录已经证明掌握的知识、误解和会影响下一步教学的洞见。用它和学习任务判断最近发展区；格式见 [LEARNING-RECORD-FORMAT.md](./LEARNING-RECORD-FORMAT.md)。覆盖过的内容不等于已掌握。
- `GLOSSARY.md` 是已掌握术语的复习和跨课查询资料，格式见 [GLOSSARY-FORMAT.md](./GLOSSARY-FORMAT.md)。它不能代替课程中的首次解释；术语收录后，后续课程优先使用该规范名称。
- 课程写入 `lessons/0001-<dash-case-name>.html`，编号递增；共享样式、测验、图示与其他可复用组件放在 `assets/`。写课前先检查现有组件，新组件应可被后续课程复用，而不是把重复代码内联。共享样式表是首个组件，每节课都链接它。
- `reference/*.html` 保存跨课可复习的速查表、算法、语法和术语表，是课程知识的压缩成果。创建课程时，为会跨课使用的知识创建或更新相应参考资料；`NOTES.md` 保存用户的教学偏好。

## 课程设计

每节课只交付一个与学习任务直接相关、处于最近发展区的单一收获，并能在较短时间内完成。短小是控制学习范围，不是删掉理解所需的解释。

- 课程是独立完整、适合复习的 HTML 文档：排版清楚、可打印，并通过 HTML 锚点链接相关课程和参考资料。图示能澄清流程、结构或因果时，使用或创建共享图示组件。
- 知识来自可信来源，技能来自练习，智慧来自现实互动。先讲获得技能所需的知识，再用有紧密、尽可能即时且自动的反馈循环练习。可用测验、浏览器内轻任务或现实步骤；测验选项尽量保持相同词数和字符数，避免格式泄露答案。
- 知识讲解应降低无关困难；技能练习则用检索、间隔和合适时的交错练习制造有益困难，建立长期存储强度，而不把当下流畅回忆误判为掌握。
- 需要真实世界检验或智慧的问题，先尽力回答，再推荐声誉良好的线上或线下社区；尊重用户不加入社区的偏好。
- 完成课程后，如可行，运行命令打开课程文件，并提醒用户可以继续向 Agent 追问不清楚的地方。

## 初学者可读性

写作或修订课程前，找出理解本课所必需的关键概念、英文全称、缩写、系统行话和易混淆符号。每个概念首次出现时就在原位置按以下顺序解释：

`中文名（English full name，缩写）` → 白话含义 → 它在当前数字案例、流程或任务中解决什么问题。

- 高风险或容易混淆的概念还要说明“它不是什么”。例如，DR/CR 表示会计方向，并不天然代表数据库金额的正负号。
- 目录、标题、练习题、反馈、代码示例和参考资料都不能把尚未解释的术语或缩写当作理解前提。术语表只用于复习和跨课查询。
- 用“具体案例 → 发生了什么 → 为什么这样处理 → 标准术语 → 系统字段、状态或代码含义”搭建认知桥梁。先白话和例子，再引入术语或实现。
- 一句话同时出现新概念、结论和例外时，拆为两到四句。保留因果、限制条件、反例和自然过渡；不以口号、反问、故作深刻的标题或“不是 X，而是 Y”式对比代替说明。

## 完稿编辑与验收

课程、参考资料或概念说明完成后，调用 `humanizer` 的 embedded mode 做最后一轮面向学习者的文字编辑。目标安装路径是 `/Users/admin/.agents/skills/humanizer/SKILL.md`；在不同用户环境中解析为该环境已安装的同一 `humanizer` Skill。

- 编辑正文、标题、提示语、题目反馈和段落过渡，去掉 AI 式口号、空泛重要性、机械三段式、模板化总结、标题复述与过度对仗；把跳跃或过短的句子改成自然、直接且有因果关系的说明。
- 保留事实、数字、来源、适用边界和不确定性。不要改写代码、公式、字段名、协议名、表格精确值、引用链接或用户提供的专业术语；不要补充任何未经现有来源、数字案例或上下文支持的新事实。
- 技术、金融和参考资料保持中性、清楚、直接的语气，不改成随意聊天。humanizer 不是压缩器：原文太简练而难读时，应补足已有资料或案例支持的解释，而不是继续删字。

每节课完成前执行两项自检：

1. **术语自检**：从本课开头随机开始读，初学者不跳转页面也能理解每个首次出现的关键术语、缩写和符号。
2. **可读性自检**：逐段确认读者能回答“发生了什么、为什么、例子是什么、它和系统有什么关系”。若只能复述结论，补足解释后再交付。

# 实施

先读取[保证等级](references/shared/adapters/assurance-levels.md)、已确认需求和 runtime 执行简报；工作边界是当前 Topic/Ticket 与适用规则。[找用户的条件](references/shared/user-intervention.md)决定哪些事项交用户。

动手前在执行简报补写实施计划：要改的文件和接口；逐条核实 Spec/Ticket 的现状断言并附代码依据；列出每个契约、共享函数、表结构、配置、锁、错误码的调用方/消费者及检查结论，检查新旧版本并存、存量数据、并发、权限、性能；每条验收分别对应独立测试断言，不共用一个测试。现状与 Spec 不符时停下按 spec-challenge 处理，不能任选一边实现。quick 在对话中形成同等计划，不伪造 Ticket 或实施记录。

将验收落到稳定 seam，调用 {{skill-call:my-tdd}} 完成最小行为切片；适用例外时记录依据及等价验证。每片跑最快有效测试，工作单元结束验证受影响链路；每张 Ticket 跑声明定向测试，批次结束跑全量测试并与基线比较。只做当前必要行为。

按[实施适配](references/shared/adapters/implementation-session.md)获取和恢复状态，不在 Skill 复制 runtime 已强制的计数、事务或完成校验。提交前记录六节增强自审：验收对照（验收→各自测试→代码位置）；现状核实（逐条断言和代码依据）；影响面（上述对象、消费者和兼容结论）；对抗检查（至少一项最可能失败路径的负向测试、探针或边界输入，命令与结果，不能执行说明原因）；简洁与约定（推测性、重复、只实现样例、分层/命名偏差及整理）；已知缺口（批次重点关注）。无内容写无及理由。高风险信号：持久状态/存量数据、并发锁、对外契约、发布回滚、改变既有行为、不可逆迁移、权限安全；多数 Ticket 不需要独立审查，只有明显高于同批次其他 Ticket 时按需触发并记录理由。批次结束调用 {{skill-call:my-code-review}} 做新上下文独立审查；高风险审查不能跳过或缩小批次范围。遵循[审查循环](references/shared/review-loop.md)登记判断与处理阻断；fix-in-batch 在已触及代码内修复，defer 写建议归属，decline 写理由。

完成当前 Ticket 后在已确认范围内按依赖继续下一张。同会话按依赖完成整个批次并逐张提交；批次末全量测试、一次独立审查、修复复审后收口。多批次最后一次审查含整个 Topic 改动清单；整分支审查可选，用户要求或跨批次共享契约风险较高时执行并记发起者与理由，修复落最后批次。按[交付规则](references/shared/workflow-delivery.md)沉淀 CONTEXT/ADR、填写全部固定摘要节，再完成 Topic；未验收闭环只能报告进度。

批次收口后 Ticket 是历史事实，补偿或迁移另建工作；需求/范围/验收失效交用户修订。环境或证据缺失如实说明，不猜测通过。

绝不为让测试或检查变绿修改与当前 Ticket 无关的文件、配置或环境。定向测试因环境不能运行，按现有环境阻塞规则报告缺失输入与最小恢复动作；全量基线无法运行的命令如实列未验证项，不改无关内容去消除失败。

为度量保留自审发现：self-review 除六节 notes-file 外，有发现传 --findings-file（M2发现数组），确实无发现传 --no-findings；不将缺记录算零。已修复的发现仍留记录，摘要标修复情况。

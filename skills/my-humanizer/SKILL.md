# Humanizer

先**分类**，再只对可改区按 [PATTERNS.md](PATTERNS.md) 去 AI 腔。依据：[Wikipedia: Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)。工作产物的策略边界见 [humanizer](references/shared/humanizer.md)。

## 分类（动笔前必做）

把输入标成两类；分不清时标为冻结。

| 区 | 含义 | 处理 |
|----|------|------|
| **可改** | 给人读的说明：背景、利弊、问题陈述、「要构建什么」、散文注释 | 可跑 PATTERNS |
| **冻结** | Agent 或工具会按字面执行/比对的表面 | **一字不改** |

冻结至少包括：预设名与策略取值；验收复选框原文；命令名与 CLI 标志；阻塞边与 Ticket 字段名/合法枚举；表格合法组合；硬性「必须 / 不得」句；frontmatter 键值；代码块；链接目标与仓库路径；`my-*` 与 Skill 主导词；机器可读 ID。

另有固定不动（不论是否像 AI）：代码块、frontmatter、数据表、链接目标。用户写作样本若存在，样本习惯压过风格细则（含破折号），但不压过冻结区。

分类未完成前不得整篇润色。

## 硬规则

1. **冻结优先于文风**：可读性让位于 Agent 可执行性；宁可不改，也不改冻结区。
2. **信息优先于形状**（仅可改区）：事实主张保留；段落可拆可并。
3. **不编造**：不新增原文没有的事实、人名、数字、日期、引文。
4. **匹配语气**（仅可改区）：贴合语域；技术/法律/参考文保持平实。

## 调用模式

- **粘贴（默认）**：交冻结摘要、可改区拟改要点、终稿（或确认前的拟稿）。
- **文件**：原地只改可改叙述；冻结区与代码块/frontmatter/数据/链接目标保持原样。对话只报：冻结了什么、改了什么。
- **嵌入**：其他 Skill 落笔一步。内部完成分类与改写，只输出终稿；冻结区必须与输入一致。

当调用方处于 `humanizer_policy: confirm`：先出示冻结清单与可改区改动，**未确认不得**写入或覆盖。

## 过程

完成条件：已完成分类；冻结区与原文一致；仅可改区有文风改动；无新事实；已按模式交付。

1. 判定模式；工作产物则加载 humanizer 边界。
2. **分类**：列出冻结项（或声明「全文无契约/可执行表面」）；其余为可改。
3. 仅对可改区按 PATTERNS 扫描；成簇才改，孤立痕迹多半是假阳性。
4. 自检：冻结区是否被碰；是否引入新事实；是否仍明显像 AI。
5. 按模式交付。confirm 时停在确认前。

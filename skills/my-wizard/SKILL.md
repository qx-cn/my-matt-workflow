# 协作式向导

为第三方配置、一次性迁移或状态转换生成 Bash 向导。向导默认保存到 `.agent/work/<topic>/wizards/wizards-<topic>-<time-or-sequence>.sh`，只用于本次经过批准的流程；迁移为可复用项目脚本或更新 README 须另行明确确认。

1. 先阅读 `.env*`、README、配置和 CI 工作流，列出每个阶段、产出值、来源、落点与是否为秘密；向用户展示顺序并确认。
2. 为每阶段给出可核对的人类路径。未知的网页步骤或命令必须询问或查阅文档，不得编造。
3. 从 [template.sh](template.sh) 复制并只编写阶段定义：每一步展示进度、打开 URL、说明操作并要求确认。对秘密使用隐藏输入，**不得回显秘密**。
4. 本地 `.env` 写入仅发生在已批准流程中。每个 GitHub Secret 或 Variable 写入都必须展示名称、用途与回滚方式，并在执行该项前单独确认；不得批量或隐式写入外部系统。
5. 运行 `bash -n`，可用时运行 `shellcheck`；静态追踪每个值的来源和落点，但不要自行端到端运行会打开浏览器或等待人类输入的向导。

完成时说明运行命令、阶段、会写入的位置与尚需人工完成的事项。

> 项目策略优先：读取 `.agent/matt-workflow.md` 的已解析生效策略；缺键或空值按 `strict-control`。本 Skill 中要求询问、确认、停止或限制后续工作的表述，除绝对安全底线外，均服从该生效策略。绝对安全底线始终不变：不得 Force Push、改写 Git 历史、执行破坏性 Git 操作，或向外部服务发送敏感信息。

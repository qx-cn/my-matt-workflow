# 向导

**向导**是一个 Bash 脚本，它逐步带领人类完成手动流程——第三方配置、一次性迁移或 A→B 状态转换；这些操作手动执行很繁琐，也不值得每次都向 AI 重新解释。它会打开每个 URL，准确说明要点击和复制什么，捕获值，将它们写入相应位置（`.env`、GitHub Secrets），在每个阶段确认，并显示还剩多少工作。它可以配置第三方服务、运行一次性迁移，或将项目从一个状态迁移到另一个状态。

界定流程和提示语时按[面向读者写作](references/shared/reader-first-writing.md)考虑执行者已有知识、当前一步、秘密处理、回退方式和完成证据；易变化的外部 UI 路径在生成时核实，不写成长期不变事实。

愉悦的 UX 已由 [template.sh](template.sh) 解决：带剩余时间的进度、确认关卡、跨平台 URL 打开（含 WSL）、隐藏的秘密输入、幂等的 `.env` upsert、`gh secret`/`gh variable` 写入，以及结束摘要。**你的工作只是在于界定流程并编写其阶段。** `STAGES` 标记上方的库在每个向导中完全相同；这种一致性正是目的——永远不要手动编辑它。

向导默认是临时的——为一次运行而构建，保存在临时目录或 `scripts/` 路径，工作完成后删除。仅当用户希望保留一个可重复使用、应当留在仓库中的配置路径时才提交它。

## 流程

### 1. 界定流程范围

确定人类必须完成的每一步手动操作，以及过程中捕获的每个值。先阅读仓库——不要凭空提问：

- 对于配置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 对于迁移或转换：当前状态、目标状态，以及其间不可逆的操作。

然后向用户展示按顺序排列的阶段及每个阶段产出的值，并确认——他们可能会增加、删除或重新排序。

**完成条件：**每个阶段按顺序命名，并且对于每个捕获的值，你知道 (a) 人类从哪里取得它，(b) 它写到哪里（`.env`、GitHub Secret、两者，或无处——有些阶段只是纯操作），以及 (c) 它是否是秘密（隐藏输入）或公开值。

### 2. 绘制每个阶段的路径

对于每个阶段，写出人类遵循的精确路径：打开哪个 URL、在那里做什么、值在哪里显示、它填入哪个变量——例如“Dashboard → Developers → API keys → Reveal test key → copy”。若你并不知道当前 UI 或确切命令，应明确说明并询问用户或查阅文档——永远不要编造可能不存在的步骤。

**完成条件：**每个阶段都能追溯到一个陌生人可以遵循的具体指令。

### 3. 编写向导

将 `template.sh` 复制到目标路径。按依赖顺序，用每一步一个 `stage` 替换示例阶段。使用库辅助函数——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并将 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设为诚实的估计值（这会驱动剩余时间显示）。

遵守模板设定的标准：在请求值之前打开 URL，对所有秘密使用 `ask_secret`，写入的每个持久化值都用 `write_env`，仅对 CI 实际需要的值使用 `set_secret`，并在任何不可逆操作之前使用 `confirm`。每个 `stage` 都会清屏，因此只有当前步骤可见——让一个阶段只处理一个聚焦任务，使人类所需内容不会滚出屏幕。不要改动 `STAGES` 标记上方的库。

### 4. 验证并交付

- `bash -n <script>`；若可用则运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自行端到端运行——它会打开浏览器并阻塞等待人类输入。应静态追踪：步骤 1 中的每个值都被捕获并落到步骤 1 所说的位置；每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全匹配。
- 告诉用户如何运行它。若这是可重复的配置路径，提交它并从 README 链接它，让下一个人运行脚本而不是向 AI 询问。

# 整理 Spec

不做访谈。复用已有讨论、PRD、决定与代码事实，将影响方案判断的缺口写为已知限制。
核实关于现状的断言，附可定位的代码位置；无法核实的内容不写成事实。

输出到 `.agent/work/<主题>/spec.md`。后续修改直接更新原文件，变更原因记在同目录的 `decided.md`，一行一条。
正文只写当前有效的目标、方案和约束。任务清单描述可交付的结果，端到端验证说明可观察的成功与失败条件。

使用下面七节模板，按实际风险说明系统影响。

```markdown
# <主题>

## 1. 目标

## 2. 不做的范围

## 3. 现状事实
附代码位置。

## 4. 方案

## 5. 系统影响
调用方、存量数据、新旧版本并存、并发与锁、回滚。

## 6. 任务清单

## 7. 端到端验证
```

# 整理 Spec

不做访谈。依据已有讨论、PRD、`decided.md` 和代码事实整理；影响方案判断但没有答案的问题，写成已知限制。
关于现状的描述要核实，并附可定位的代码位置；核实不了的不写成事实。

写入 `.agent/work/<主题>/spec.md`。之后的修改直接改原文件，变更原因记进同目录的 `decided.md`，一行一条。
任务清单写可交付的结果；端到端验证写可观察的成功和失败条件。

默认用下面七节；小改动可以合并或省略无关的节。

```markdown
# <主题>

## 1. 目标

## 2. 不做的范围

## 3. 现状事实
附代码位置。

## 4. 方案
写明涉及的文件和接口。

## 5. 系统影响
调用方、存量数据、新旧版本并存、并发与锁、回滚，按实际风险写。

## 6. 任务清单

## 7. 端到端验证
```

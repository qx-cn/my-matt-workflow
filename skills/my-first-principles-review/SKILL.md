# 第一性原理审查

当用户明确要判断一个已形成的提案、决定、流程、制度、产品机制或技术设计“从根本上是否成立”时使用本 Skill。它是建议性专项审查：不修改对象、不替用户做产品取舍，也不产生 `my-review-artifact` 的正式交付 receipt。

判断技术设计是否闭环并足以实施时使用 `my-review-design`；审查代码正确性使用 `my-code-review`；判断 Skill 是否应存在或应迁入 runtime 使用 `my-review-skill`；需要固定快照、跨维度检查和正式交付 Verdict 时使用 `my-review-artifact`。

读取对象及其直接引用的最小事实来源，并应用[第一性原理推理](references/shared/first-principles-reasoning.md)：

1. 固定审查对象、目标读者和要支持的决定。只有存在会改变对象边界的多种合理理解时，才询问一个最小问题。
2. 重建使用者可观察的真实目标；将事实、假设和未知按共享来源分类，不能查证的承重事实保持未知。
3. 检查目标到机制再到用户结果的因果链，识别把手段、类比、惯例或局部指标当成目标的情况。
4. 对承重选择比较维持现状、删除机制或一个更小替代方案；检查额外复杂度是否产生可观察收益。
5. 检查可证伪预测和验收证据能否捕获失败，而不是只证明步骤执行过。

只报告会改变采用、修改或放弃决定的问题，同一根因去重。每项说明对象位置、失败的推理环节、事实或假设依据、对用户结果的影响、最小修正方向和最小验证。

最终只给出一个 Verdict：

- `HOLDS`：目标、因果链、反事实和验收成立，没有影响决定的证据缺口；
- `HOLDS_WITH_GAPS`：核心机制成立，只有不会推翻它的可解除证据缺口；
- `VIOLATES`：目标替换、关键因果断裂、无收益复杂度或验收错位会改变决定；
- `INCONCLUSIVE`：缺少承重事实，无法判断核心机制是否成立。

没有通过准入的 finding 时写 `No findings.`。不要输出逐项通过清单、泛化哲学、领域专项结论或未经请求的改写稿。

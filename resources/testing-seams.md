# 测试 Seam 合同

测试通过调用方可观察的稳定 seam 验证行为。优先使用现有公共接口；如果当前 Ticket、Spec 与代码无法共同确定 seam，且新增或改变公共接口会扩大范围或测试投资，先暂停确认。

模块也可以拥有私有的内部 seam，供该模块自身测试与替换内部机制。内部 seam 不是产品公共 API；测试应从模块边界驱动它，避免直接断言私有实现细节。

Adapter 把不可控系统边界变成可替换 port。时间、随机数、文件系统、数据库与第三方 API 可在这个边界使用 fake、测试数据库或 mock；项目自有的普通模块和内部协作者使用真实实现。一个 mock 只代表测试替身，不证明抽象值得存在；生产 seam 应由真实变化轴或至少两个实际 adapter 证明。

选择替身时保留边界语义：具体操作接口优于带条件分支的通用 fetcher；断言可观察请求与结果，不复刻实现算法。测试结束后，重构可以改变内部结构，只要同一 seam 上的行为保持不变。

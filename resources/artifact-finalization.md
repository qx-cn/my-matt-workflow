# 产物最终校验

在 Spec、handoff 或其他承重文档标记为终态、发布或交给下一 Agent 前，执行以下四个独立 gate。每项只判断 `pass` 或 `blocked`，不得用总分让一项问题抵消另一项。普通叙述不需要逐句建账；只检查会改变目标、范围、公开接口、数据语义、验收、风险承担或下一步动作的主张。

为了恢复工作，可以持久化明确标为 `draft` 的承重草稿。草稿必须记录未通过的 gate、影响和解除动作，不得称为已发布、可直接继续或可交接；敏感信息尚未移除时连草稿也不得保存。具体 Skill 可以采用更严格的“不保存草稿”规则。

## 1. 来源账本

为每条承重主张标明一种来源：`user-confirmed`（用户已确认的决定）、`repository`（当前代码、规则或 ADR）、`external`（带 URL、版本或日期的一手来源）、`execution`（测试、命令或原型结果）、`assumption` 或 `unknown`。来源必须能定位；聊天印象和模型记忆不能冒充证据。成品只需保留影响读者决策的依据、假设与未知，不机械展示完整工作表。

## 2. 内部一致性

检查目标、范围、术语、约束、状态、流程、验收与下一步是否互相支持；同一概念不得在不同章节改变含义。按最终态写作移除已被取代的方案。发现矛盾时列出冲突位置和受影响结论，在解决前标记 `blocked`。

## 3. 读者重建

使用未参与撰写的上下文，或清空结论后进行 fresh-context 阅读，让审阅者仅从成品重建：目标、范围外、已确认决定、未解决问题、验证证据和下一步。将重建结果与来源账本比较。遗漏或误读会改变实施或决策时标记 `blocked`；只影响文风时直接精简或澄清。

## 4. 事实正确性

按主张类型复核，不输出笼统“正确性分数”：

- `repository`：重新读取当前路径、规则、ADR 或 Commit；路径、版本和状态必须仍有效。
- `external`：回到一手来源，保留 URL、版本或访问日期；时效不明则标为未知。
- `execution`：核对实际命令、退出码和原始结果；需要运行才能确认的行为不得只靠推断。
- `user-confirmed`：能回指明确确认，不能把 Agent 建议改写成用户决定。
- `assumption` / `unknown`：公开标注影响和解除方式；若它会改变承重决策，gate 为 `blocked`。

四项全部 `pass` 后才可标记为终态、发布或交接。校验后的润色不得新增事实、改变结论或删除仍影响决策的未知；发生这类变化时重新执行四项 gate。

## 审查应用

只检查会改变目标、范围、公开接口、数据语义、验收、风险承担或下一步动作的主张。分别运行来源账本、内部一致性、读者重建和事实正确性四项 gate；一项失败不能被其他项抵消。需要核实仓库、执行或外部来源时读取相应证据，不能获得的承重证据标为未知。

每个发现给出主张位置、失败的 gate、可定位的证据、影响及解除方式；同一根因跨 gate 出现时合并，并列出所有受影响 gate。四项全部通过时写 `No findings.`；不得用总分、笼统正确率或无证据的通过清单代替结论。

# 按读者选择表达

根据内容类型和目标读者选择能明显降低理解或解析成本的形式。面向人类时，复杂依赖、条件流程、跨方协作、状态迁移或精确对照可用关系图、流程图、时序图、状态图或表格；简单内容直接文字。面向 Agent 的 Spec/Prompt/Skill/Ticket 优先明确结构、显式约束与低歧义可解析文字，仅复杂关系确有收益时用图。内容类别本身不强制图示。

教学内容/前端分阶段时，content 用 visual_intent 记录图要回答的问题和已确认关系；不指定像素、布局或配色。可选择 none 并解释文字为何足够，不仅限于纯结论。frontend 实现非 none 意图；只有承重关系缺失、歧义或无法据此准确渲染时才 blocked-by-content，不能仅凭内容属于结构/流程而阻断 none，也不能自行发明事实。

每张图回答一个核心问题，紧邻结论；复杂时拆图。节点与连线保留必要短标签，长条件和例外放邻近正文。关键规则、结论和答案有文字定义，不能只在图里。对照有明确分隔；数值与备注分列；溢出、叠字、遮挡、截断或连线归属不清需修复。

共享规则不规定 CSS 类名或模块清单，实际节点使用材料确认的项目术语。具体图形/输出格式服从宿主规范；Markdown可用Mermaid，HTML可用SVG或组件，但不为格式偏好造图。

## 审查应用

审查已有产物时只读，检查是否存在具体理解障碍、图形错误或为画图而画图；关键规则是否可从文字重建。每项发现给位置、目标读者的障碍及最小调整方向，不因无图自动制造发现。没有合格发现写 No findings.。

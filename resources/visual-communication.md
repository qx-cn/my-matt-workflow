# 图示表达

面向人类的教学课页只要包含下列结构、关系、顺序、分支、状态或多项对照，默认必须使用最小且恰当的视觉表达：

- 系统边界与依赖：架构图或关系图；
- 步骤、条件与异常：流程图；
- 跨角色或跨系统协作：时序图；
- 状态迁移：状态图；
- 多项精确对照：表格。

采用内容/前端分阶段的教学 Skill，在内容阶段用 `visual_intent` 记录图要回答的问题和数据关系，不指定像素、布局或配色。只有纯结论、短步骤、少量字段或短列表可以写 `visual_intent: none`，并说明文字为何已经足够；不能以制作成本、缺少配图或前端可以自行理解为理由写 `none`。

教学前端必须实现每个非 `none` 的意图。明显属于系统结构、条件流程、跨方协作或状态迁移却标为 `none` 时，应返回 `blocked-by-content` 并指出所在 `section_id`，不得自行发明事实；也不得用缺少关系、方向或顺序的一排 CSS 盒子冒充架构图或时序图。

图只回答一个核心问题，并紧邻对应结论；一个画面无法清楚回答两个问题时拆图。架构图和关系图默认只保留节点、边及理解关系所需的短标签，较长条件、例外和段落放在邻近正文；流程图或状态图的分支条件可以保留在对应边上，但复杂规则仍由图外文字定义。文字补充结论、原因与约束，不重复图中已经清楚表达的关系；关键规则和答案仍须用文字表达，不能只存在于图中。

左右对照要有明确分隔；数值与备注承担不同阅读任务时分列，不挤进同一标签或文本块。字溢出、叠字、遮挡、截断或必须猜测连线归属，都表示图尚未完成。

共享规则与内容阶段的 `visual_intent` 不规定 CSS 类名、页面组件或特定项目的模块清单，这些留给前端规范和专题材料。实际图示可以使用当前主题中经材料确认的真实模块、角色和领域名称。

其他文档仍按读者任务判断图示是否明显降低理解成本。Markdown 默认使用 Mermaid；HTML 使用原生 SVG 或页面组件。宿主 Skill 已有更具体的图形或输出规范时，以其规范为准。

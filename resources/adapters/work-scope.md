# 实施范围

已确认用户目标、预期外部行为、验收语义、明确限制与风险承诺决定授权。Ticket 组织工作、依赖和验收归属；touchpoints、旧 rule_scope、原实施计划都是提示。按真实调用方与消费者完成目标所需的跨模块修改、相关修复、整理、测试和文档同步，不申请技术扩围；生命周期与技术刷新由[实施适配](implementation-session.md)定义。

发现事实错误或计划漏项，直接更新实施计划及受影响的未完成定义，记录调整依据、调用方与消费者、验收归属和验证结果，保持 Spec 版本血缘及验收覆盖。定义变化或已有技术挑战处置用 refresh 失效旧验证；产品裁决仍用 accept/reopen。完成历史不回写，后续必要修复另建补偿工作继续既有目标。

需要改变已确认目标、外部行为、验收语义、明确限制或风险承诺时，按[用户决定与授权](../user-intervention.md)处理；未验收闭环只能报告进度。

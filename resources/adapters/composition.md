# 组合调用适配

组合清单把边分成三类，不能只凭“调用另一个 Skill”决定是否停止：

- `router`：`routable_entries` 中的用户入口。只命名下一跳，不打包；输出显式调用后停止。
- `method`：`callers` 中由宿主完成自身职责所需的方法。构建时打包；当前阶段读取正文、执行后返回宿主，不输出另一条 Skill 调用，也不因 `manual` 停止。
- `handoff`：`callers` 中从已完成阶段进入另一个可独立流程的交接。构建时打包；只有当前阶段已完成且下一阶段已获授权时才能继续。

调用方式：

- `automatic`：对当前阶段需要的 `method` 读取已打包正文并在完成后返回宿主；对已获授权的 `handoff` 读取已打包正文继续。
- `manual`：`method` 与 `automatic` 相同，直接执行并返回宿主；`handoff` 输出当前运行时对应的显式调用后停止。

用户显式调用只满足当前入口的调用门槛，不会自动授权未批准的 `handoff`。安全门禁、写入授权和 Ticket 准入不受组合策略影响。

已打包依赖的 Skill 正文固定命名为 `references/composed/<skill>/COMPOSED.md`。这是供宿主读取的参考副本，不是可调用 Skill；顶层 `SKILL.md` 才是运行时注册入口。

`method` 完成后，控制权和结果回到宿主，由宿主继续后续步骤；被调用正文中的通用结束语不能提前结束宿主流程。`handoff` 则把控制权交给下一入口。阶段内可暂停的普通确认点由宿主的工作范围与决策策略判定，不能由被调用 Skill 的旧默认文案单独覆盖。

此适配只决定组合调用方式，不改变被调用 Skill 的停止条件、确认门槛或其他上游方法。

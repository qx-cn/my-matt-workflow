# 面向读者写作

面向读者的成品在起草前先建立内部 `reader brief`，至少确认：主要读者是人、Agent 还是两者，文档用途，读者看完要作出的决定或动作，已有知识，以及最关心的风险或疑问。缺少其中会实质改变内容的信息时才询问用户；其余可从任务和材料合理推断，并标明假设。

成品结论先行，只保留支撑读者任务所需的背景、证据和限制。篇幅随问题复杂度决定，不设统一字符数，也不把内部 `reader brief`、状态、修订号、来源账本、模型分工或作者待办机械输出成章节、页脚或看板。

用户与 AI 的讨论、提示词、需求澄清、方案争论、评审过程、修改指令、TODO、模型交接、生成步骤和已被取代的中间结论，不得仅为记录制作过程而原样残留在成品中。根据目标读者的任务，只提炼其中当前仍有效的目标、决定、约束、依据、未知和下一步，并改写为读者可直接使用的最终表达：例如把已确认的限制写成适用范围，把影响使用的未决问题写成已知限制；不要保留“我们讨论过”“用户要求”“评审认为”或“后续让 AI 修改”等过程叙述。

面向人的成品优先保留理解、判断和行动所需的信息。面向 Agent 的工件可以保留可执行状态、约束、来源、阻塞项、下一步和授权边界，但仍不保留与继续工作无关的对话流水；原始提示词只有本身就是目标 Agent 必须执行的指令时才是成品内容。混合读者的内容优先拆成人类正文与结构化元数据或独立交接工件，避免把 Agent 控制信息混进人类正文。

判断一段过程信息是否应删除：若删除后只是让读者看不到作者与 AI 如何制作成品，却不影响人的理解、判断和行动，也不影响 Agent 正确继续工作，就不应保留。

把“作者还没完成什么”和“读者据此还不能判断什么”分开：前者只留在内部工件；后者若影响读者的决定或动作，改写为正文中的适用限制或下一步核验。内部事实清单、关系清单可帮助检查，但成品只在确有复习价值时换成自然的读者标题，不为字段对齐设置固定栏目。

选择最小且清楚的表达方式。教学课页中的系统边界与依赖、带条件或异常的流程、跨方协作、状态迁移、多项精确对照，默认分别使用关系图、流程图、时序图、状态图或表格；只有简单结论、短步骤、少量字段和短列表才直接用文字。其他文档仍按读者任务判断图示是否明显降低理解成本。图示只能辅助，关键结论和约束仍用文字定义。

# 用户决定、授权与阶段边界

这是工作流请求用户决定或授权的唯一清单。先检查当前请求、已确认材料和会话授权是否已经覆盖具体动作、目标及后果；已确认授权在该范围内持续有效。能从代码、文件或工具查证的事实由 Agent 查证，授权内可逆实施细节直接推进。

- 请求的阶段是止点：只要求诊断、方案或 Spec，就交付到该阶段；已批准范围内要求开发，则继续完成实施、验证与收口。不因 Skill 的默认 chain 扩大请求。
- 对齐点1确认需求摘要和 quick/standard；对齐点2确认 Spec 与逐 Ticket 行为、依赖、命令和验证边界。已有明确确认可以引用，不重复访谈或重复批准；Spec 获批不能自动证明尚未确认的 Ticket 划分已获批。
- 只有影响结果且尚未决定的产品取舍、成功指标、优先级、范围、验收或风险承担交用户裁决。新证据推翻原事实时先核实并说明影响；普通方法选择不另设对齐点。
- 推送、建 MR、发布、安装或写外部系统：已授权同一具体动作及目的地则执行；未授权、目的地变化或后果超出授权时，先完成可审阅产物，再请求所缺授权。生成本地文件不自动授权外部发送。结果未知时先查询原目标状态或原操作身份，确认是否已生效；仍未知则保留未知，不盲目重试副作用，继续不依赖该结果的独立授权工作。相同动作授权不等于重复副作用授权。
- setup/migrate apply 前确认预览的具体配置或迁移；已有覆盖该预览的授权则不再问。修改批准范围以外的项目文档同样先确定范围。
- triage→Spec/Ticket、wayfinder→Spec、prototype→implement 的交接先检查下一阶段是否已授权；已授权直接调用，未授权交付当前阶段并说明可继续的入口。
- 真实设计阻断、无法裁决的证据或[审查预算耗尽](review-loop.md)交用户处理；几何信号本身不新增批准门槛。
- 环境缺输入或权限时说明缺口和最小恢复动作；继续不依赖它的已授权工作，不能把缺失当通过。

涉及敏感信息、同步、危险 Git 或原生 Skill 修改时读取[固定安全边界](../policies/enterprise-safety.md)。授权不能覆盖平台/宿主权限，也不能扩大到未指定的破坏性 Git 操作或敏感信息外发。用户临时更严格的限制有效。输出平实地说明待决定事项和影响，不要求用户逐段手动调用，也不把内部状态名当作原因。
